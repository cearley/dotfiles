# Proposal

## Why

An external Codex CLI code review of this repo (2026-09-28) found three high-severity defects that each turn a working-as-designed mechanism into a security or bootstrap-reliability gap: (1) KeePassXC-sourced secrets are interpolated into shell scripts and shell-sourced files with chezmoi's `quote` template function, which produces a JSON-style double-quoted string, not a shell-safe one — a secret value containing `$(...)` or a backtick is executed as a command when the file is sourced or run (reproduced with synthetic data: `literal$(printf INJECTED)$HOME` rendered as `literalINJECTED/Users/craig`); (2) `home/private_dot_cloudflared/private_cert.pem.tmpl` decrypts a SOPS+age-encrypted file at chezmoi template-render time, but the age private key that decryption depends on is installed by `run_onchange_after_darwin-43-setup-age-key.sh.tmpl`, a `run_onchange_` script — and chezmoi renders template target files and runs `run_onchange_` scripts as part of the same ordered apply pass, so a fresh machine with no age key yet on disk has no guaranteed way to reach script 43 before `cert.pem`'s template needs to decrypt; (3) `apply-claude-pattern c` refuses to write `bypassPermissions` without container-isolation evidence at the moment it is invoked, but the companion Pattern C devcontainer bind-mounts the same host checkout that received the stamp, so once the container exits, `.claude/settings.local.json`'s `bypassPermissions` mode is still there and still live for ordinary host (non-container) Claude Code sessions in that repo — the isolation check only ever runs at stamping time, never at use time.

All three are correctness/security gaps in mechanisms this repo already ships (secret rendering, SOPS+age bootstrap, `claude-repo-permission-patterns`), not new capabilities, and fixing them now — before broader medium-severity cleanup — is what Codex's own priority ordering recommended (shell escaping → bootstrap ordering → Pattern C isolation, ahead of any other maintenance work in the review).

## What Changes

- **Shell-safe secret interpolation**: audit every chezmoi template that renders a KeePassXC-sourced (or otherwise externally-controlled) secret into a shell-variable-assignment or shell-argument context — confirmed sites: `home/private_dot_zsh_secrets.tmpl`, `home/private_dot_config/mcp-env/private_localstack-mcp-server.env.tmpl`, and the `.sh.tmpl` scripts `run_onchange_after_darwin-45-setup-github-auth`, `-46-setup-ssh-github`, `-47-setup-azure-auth`, `-48-setup-azure-auth-personal`, `run_once_after_darwin-83-login-atuin` — and switch each from `| quote` (JSON-style double-quoting; does not neutralize `$()`/backtick expansion) to chezmoi's `shellQuote` template function (POSIX single-quote escaping) for that specific interpolation. Templates that render into a non-shell context (JSON, TOML, `home/.chezmoi.toml.tmpl` config data) are explicitly out of scope and keep `quote`.
- **SOPS/age bootstrap ordering**: give `home/private_dot_cloudflared/private_cert.pem.tmpl`'s `sopsDecrypt` call (and any other SOPS-decrypting template) a defined, enforced dependency on the age private key already being materialized at `$KEY_FILE`, instead of relying on `run_onchange_` numeric ordering alone to make that true. Exact mechanism (an explicit pre-render guard in the `sopsDecrypt` partial with an actionable error, moving key installation to a phase chezmoi guarantees runs before any template renders, or both) is decided in design.md.
- **Pattern C host-leak containment**: change `apply-claude-pattern c` and/or the companion devcontainer template so that a `.claude/settings.local.json` written for container use does not remain live and readable by a host (non-container) Claude Code session once the container exits — mechanism (writing Pattern C to a container-only path outside the bind-mounted tree, an isolation check that also runs at Claude Code session start rather than only at stamp time, or an explicit teardown step) is decided in design.md, along with which is structurally hardest to bypass by accident, matching this repo's existing preference (Decision 4 of `claude-repo-permission-patterns`' own design.md) for a structural fix over a documentation-only warning.

**Non-goals**

- No change to the KeePassXC-vs-SOPS+age secret-tiering model itself (`secret-management`, `sops-age-encryption`) — this change fixes *how* a secret already destined for a shell context is escaped and *when* a SOPS-decrypting template is safe to render, not which tier a given secret belongs to.
- No attempt to fold in the medium-severity Codex findings (SDKMAN/uv install-order gaps, install scripts swallowing failures, private pip index dependency-confusion risk, stale LaunchAgent on persona removal, incomplete package-audit declaration model, unpinned `.chezmoiexternal` branches, CI not exercising real config). None of them share this change's implementation surface (shell-escaping sweep, SOPS/age render-time guard, Pattern C isolation lifecycle) or its urgency tier per Codex's own priority order; each is better scoped as its own follow-up change if pursued.
- No retroactive migration of the ~200-entry `.claude/settings.local.json` this repo's own checkout has already accumulated, beyond what Pattern C's fix requires for correctness.
- No new chezmoi capability/spec path — all three fixes extend existing capabilities' behavior.

## Capabilities

### New Capabilities
(none)

### Modified Capabilities
- `secret-management`: adds a requirement that a secret interpolated into a shell-execution context (a `.sh.tmpl` script body or a shell-sourced dotfile) SHALL be rendered with shell-safe quoting that neutralizes command substitution, not `quote`'s JSON-style escaping.
- `script-execution`: adds a requirement that a template whose rendering depends on a prerequisite normally installed by a `run_onchange_`/`run_once_` script (e.g. a decryption key) SHALL NOT rely on script/template apply ordering alone to guarantee that prerequisite exists — it SHALL fail with an actionable error, or the prerequisite SHALL be installed in a phase chezmoi guarantees precedes template rendering.
- `cloudflare-tunnel-management`: adds a requirement specific to `cert.pem`'s SOPS+age decryption path enforcing the above ordering guarantee, as the concrete site where the gap was found (existing requirements describing pre-SOPS+age `keepassxcAttachment` provisioning are left as-is here — they are superseded by the still-unsynced `sops-age-secrets-pilot` change's own delta, not by this one; see Impact).
- `claude-repo-permission-patterns`: modifies the "Pattern C requires evidence of container isolation" requirement so isolation is enforced for the life of the stamped settings, not only at the moment of stamping, closing the host-checkout bind-mount leak.

## Impact

- **Affected templates/scripts**: `home/private_dot_zsh_secrets.tmpl`, `home/private_dot_config/mcp-env/private_localstack-mcp-server.env.tmpl`, `home/.chezmoiscripts/run_onchange_after_darwin-{45,46,47,48}-*.sh.tmpl`, `home/.chezmoiscripts/run_once_after_darwin-83-login-atuin.sh.tmpl`, `home/private_dot_cloudflared/private_cert.pem.tmpl`, `home/.chezmoiscripts/run_onchange_after_darwin-43-setup-age-key.sh.tmpl`, `home/.chezmoitemplates/sopsDecrypt` (or wherever that partial is defined), `home/dot_local/bin/executable_apply-claude-pattern.tmpl`, `home/.chezmoitemplates/claude-pattern-c-devcontainer/`.
- **Affected tags**: `ai` (secret-rendering and Pattern C templates are already `ai`-tag-adjacent), no new tag introduced.
- **Pre-existing, unsynced change**: `openspec/changes/sops-age-secrets-pilot/` has all 27 tasks complete but has not been archived/synced into `openspec/specs/` — its own delta already plans to update `cloudflare-tunnel-management` and introduce `sops-age-encryption` to reflect the SOPS+age migration this repo's code has already deployed. This change's `cloudflare-tunnel-management` delta is additive (a new requirement) specifically to avoid colliding with that pending, unsynced modification; reconciling the two at archive time is expected and is not this change's job to pre-resolve.
- **Security implications**: this is a security-hardening change with no feature surface — (1) closes a command-injection vector triggered by secret *values*, not attacker-controlled input, but KeePassXC entries can still contain unexpected characters (copy-paste artifacts, generated passwords) that would otherwise execute; (2) turns a silent bootstrap failure mode (fresh machine, no age key, cert.pem template errors or renders garbage) into either a guaranteed-safe order or a clear, actionable failure; (3) closes a real privilege-persistence gap where a sandboxed, `bypassPermissions` posture intended only for container use keeps applying to ordinary host sessions in the same checkout. No new secrets or credentials are introduced by this change.
