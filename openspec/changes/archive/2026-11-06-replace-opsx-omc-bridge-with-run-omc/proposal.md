# Proposal

## Why

`opsx-omc-bridge` is declared in `packages.yaml` and installed on every machine via the `ai` tag, but it is unused: nothing in this repo references it, and the sister C#/.NET project (`WES.ViewPoint.CommonMicro.API`) that evaluated it explicitly rejected it for autonomous OpenSpec runs — its ralph/autopilot paths each carry a second task ledger that competes with `tasks.md`, the single source of truth OpenSpec itself already provides via `openspec instructions apply --json`. That project instead built a project-local `/opsx:run-omc` orchestrator: preflight, then OMC `executor` subagents one phase at a time, then a parallel verify pass, then a bounded fix loop, with the orchestrating session as the only writer of `tasks.md`. It has proven out piece by piece (preflight, the stop gate, a live executor run, the verify passes) though not yet end to end.

This repo already has the OpenSpec side of that pattern (`openspec/config.yaml`, the generated `.claude/commands/opsx/*.md` set) and several of the chezmoi-specific verification pieces (`validate-template.sh`, `template-reviewer`) but no orchestrator to drive a change autonomously. Porting the pattern now gives this repo the same one-command, single-task-ledger workflow, and removes the rationale for keeping `opsx-omc-bridge` installed anywhere.

## What Changes

- Remove `opsx-omc-bridge` from `home/.chezmoidata/packages.yaml`: both the `plugin_marketplaces` entry (`https://github.com/KyongSik-Yoon/opsx-omc-bridge`) and the `plugins` entry (`opsx-omc-bridge@opsx-omc-bridge`), under `packages.darwin.ai.agents.claude_code`.
- Uninstall the plugin and remove its marketplace registration on this machine (the only one currently provisioned), so local state matches the declaration before the next `chezmoi apply` would otherwise have nothing to converge.
- Add `.claude/commands/opsx/run-omc.md`: a project-local orchestrator (explicitly not generated by `openspec update`, matching the source pattern) that runs a change's remaining tasks end to end — preflight, `oh-my-claudecode:executor` subagents one phase at a time, task marking from evidence, a parallel verify step (`code-review` skill, `opsx:verify` skill, and the existing `template-reviewer` agent when any `.tmpl` file changed), a bounded fix loop, and a READY TO MERGE / BLOCKED report. It never commits, pushes, or archives.
- Add `.claude/scripts/opsx-preflight.sh`: a read-only preflight script adapted for chezmoi — change validation, task progress/strategy, stale `.omc/prd.json` detection, an untracked-file baseline for the verify step's `git add -N`, and a dirty-tree check across all tracked files (not just one language's files, since this repo has no single compiled language).

## Capabilities

### New Capabilities
- `opsx-run-omc`: a project-local orchestrator command that autonomously implements, marks, and verifies an OpenSpec change's remaining tasks in this repo, with the orchestrating session as the single writer of `tasks.md`.

### Modified Capabilities
(none — removing a declared-but-unused plugin from `packages.yaml` is a data change within the existing `package-management` capability's schema, not a change to that schema's requirements)

## Impact

- **Affected files**: `home/.chezmoidata/packages.yaml` (remove 2 lines); new `.claude/commands/opsx/run-omc.md`; new `.claude/scripts/opsx-preflight.sh`.
- **Affected tags**: `ai` only.
- **Affected machines**: this machine, immediately (local uninstall); any other machine with the `ai` tag converges on its next `chezmoi apply` (nothing to uninstall there since none is yet provisioned beyond this one).
- **Security implications**: none. No secrets are involved; `opsx-preflight.sh` is read-only; `run-omc.md` never commits or pushes and only ever edits `tasks.md` under one change directory.
- **External dependencies**: removes one (`opsx-omc-bridge` and its marketplace); adds none.

## Non-goals

- No build-test-gate `Stop`/`SubagentStop` hook, no `shfmt` integration, and no Bash secrets-guard hook for this change. The existing `validate-template.sh` (render-check) and `template-reviewer` agent are reused as-is for the verify step. These are deferred to a follow-up change once `/opsx:run-omc` has been exercised at least once in this repo — mirroring the source project, where the same hook was added only after its preflight and executor pieces were individually proven.
- No Go-template static type-checker (e.g. `tooolbox/check`/`typelate/check`). This repo's `.tmpl` corpus has no `{{ define }}`/`{{ template }}` reusable-partial blocks today, which is where that class of tool adds value; the existing render-check (`chezmoi execute-template` via `validate-template.sh`) and the CI invariant checks already cover this repo's actual template failure modes.
- Not re-architecting `opsx-omc-bridge` into a reusable, cross-repo plugin. `/opsx:run-omc`'s verify-step conditionals are inherently tied to this repo's domain the same way the source project's are tied to C#/Fulcrum; each repo gets its own project-local orchestrator rather than a shared, genericized one.
- Not changing anything under `openspec/config.yaml` — its existing chezmoi-specific `context`/`rules` are reused as-is by the new orchestrator.
