## Why

The `claude_env` Powerlevel10k segment (from `home/.chezmoitemplates/claude-environments`) has no way to hide itself while the active Claude Code environment equals the machine's default — unlike p10k's own `aws`/`nvm` segments, which were just configured to hide "baseline" state and only surface a switch away from it. Adding that toggle surfaced a bigger opportunity: the underlying switcher logic (`claude-<name>` wrapper functions, the `claude-env` session switcher, terminal-title integration, and the p10k segment itself) is modeled directly on oh-my-zsh's built-in `aws` plugin and is generic enough to be useful outside this dotfiles repo. On reflection, the extraction should go further than originally scoped: the plugin should be fully self-contained (discovering its own environments from the filesystem, needing no chezmoi-rendered configuration at all), so that chezmoi's involvement shrinks to exactly three things — pulling the plugin's source, listing it as an oh-my-zsh plugin, and hosting its display preferences alongside every other Powerlevel10k setting.

## What Changes

- Extract the generic Claude-environment feature — per-env wrapper functions, the `claude-env` switcher, the p10k segment (with the new `CLAUDE_ENV_SHOW_DEFAULT` toggle), and terminal-title OSC-0 hooks — into a standalone oh-my-zsh-style plugin, `zsh-claude-env`, scaffolded locally at `~/work/zsh-claude-env` and published to `github.com/cearley/zsh-claude-env`.
- **Design-review scope narrowing (2026-08-03, plugin commit `3994401`, tagged `v0.2.0`)**: SpecStory wrapper functions and the session-index project list, both originally scoped into the plugin (see below), were narrowed back out entirely. `SESSION_INDEX_PROJECTS` is no longer exported by anything in this repo or the plugin — `claude-session-index` (a separate sibling tool) now self-discovers `~/.claude-*/projects` on its own, independent of this change. SpecStory wrapper functions (`claude-spec`, `codex-spec`, `gemini-spec`, `claude-<name>-spec`) turned out to have no actual relationship to Claude-environment *switching* — the same reasoning already applied to `openspecui` below — so the three non-per-env wrappers move to a plain inline block in `home/dot_zshrc.tmpl` instead (zsh only; bash still gets none, consistent with the existing bash breaking change below).
- The plugin discovers which Claude environments exist by globbing `$HOME/.claude-*` directories at load time — it requires **no** chezmoi-rendered list of environment names, colors, or defaults to function. This is what makes it genuinely self-contained and portable to any oh-my-zsh user, not just this dotfiles repo.
- Add `home/.chezmoiexternal.toml.tmpl` entry for `.oh-my-zsh/custom/plugins/zsh-claude-env`, using the same archive-tarball pattern already used for `zsh-autosuggestions`/`zsh-defer`/etc. **This entry can only be applied successfully once the plugin repo is actually pushed to GitHub** — until then it is specified but not yet appliable; sequencing this correctly is a task-list concern, not a spec concern.
- Add `zsh-claude-env` to `plugins=(...)` in `home/dot_zshrc.tmpl`, alongside the repo's other oh-my-zsh plugins.
- Move the plugin's display preferences (`CLAUDE_ENV_DEFAULT`, `CLAUDE_ENV_COLORS`, `CLAUDE_ENV_SHOW_DEFAULT`) into `home/dot_p10k.zsh` as plain, hand-edited `typeset` lines — the same way every other Powerlevel10k tuning parameter in that file works. These are read only at prompt-render time (inside `prompt_claude_env()`), which is safe even though `dot_p10k.zsh` is sourced after oh-my-zsh loads the plugin.
- **BREAKING**: `home/.chezmoitemplates/claude-environments` and every partial planned for this feature in the prior version of this proposal (`claude-env-names`, `claude-env-config`, `claude-environments-bash`) are removed entirely — not slimmed, not replaced. Nothing named `claude-env*` remains in the chezmoi source tree. Chezmoi's Claude-environments footprint becomes exactly: the `.chezmoiexternal.toml.tmpl` entry, the `plugins=()` entry, and the `dot_p10k.zsh` settings block.
- **BREAKING**: bash loses the interactive conveniences — no `claude-<name>` wrapper functions, no `claude-env` switcher, no title hooks, no SpecStory wrappers, no session-index list — for a human typing directly into a bash login shell. Oh-my-zsh is zsh-only and chezmoi no longer hosts a bash-side reimplementation of any of it. `home/dot_bashrc.tmpl` loses its `claude-environments` include with no replacement for these specific conveniences.
- **Not a regression** (verified empirically this session): Claude Code's own Bash-tool invocations and Task-tool subagents are unaffected by the bash-support drop above. They run as child processes of the `claude` binary itself and inherit `CLAUDE_CONFIG_DIR` through ordinary OS process-environment inheritance — nothing about bash's *own* shell configuration is involved. Confirmed by inspecting this session's own process ancestry: the Bash tool's shell → `claude` → the interactive zsh login shell that launched it, with `CLAUDE_CONFIG_DIR` present at every level.
- Chezmoi retains one small piece beyond the three plugin-wiring items: a default-`CLAUDE_CONFIG_DIR`-export snippet, duplicated inline (not a new partial) directly in both `home/dot_zshrc.tmpl` (placed before `plugins=(...)`) and `home/dot_bashrc.tmpl`, driven by the already-live `claude_default` config.yaml key. This restores automatic default-env behavior for every shell — including SSH sessions and bash — not just GUI-launched terminals, which is a strict improvement over the immediately-prior version of this proposal (which dropped default-export from every shell) and over the state before this whole change (which only worked in zsh/bash rc files, not via the LaunchAgent's broader GUI-session reach).
- Because that snippet now runs *before* `plugins=(...)` loads the plugin, `zsh-claude-env` no longer needs a chezmoi-rendered `CLAUDE_ENV_DEFAULT` variable at all — it captures whatever `CLAUDE_CONFIG_DIR` was already set to at its own load time as the implicit default for the show/hide-on-default comparison. `dot_p10k.zsh`'s settings block shrinks to just `CLAUDE_ENV_COLORS` and `CLAUDE_ENV_SHOW_DEFAULT`.
- The `openspecui` alias, previously co-located in `claude-environments` for convenience only, moves to a bare inline line directly in `dot_zshrc.tmpl`/`dot_bashrc.tmpl` — it has no relationship to Claude environments and doesn't belong in a plugin named `zsh-claude-env`.
- `home/.chezmoidata/config.yaml`'s `claude_env_colors` key became unused by chezmoi (nothing renders it anymore — colors moved to a hand-edited `dot_p10k.zsh` variable) and was removed outright on 2026-08-03 (task 7.1) once no machine was found to actually set it. `claude_envs` and `claude_default` remain fully in use — **not** dead config, corrected from an earlier draft of this proposal — consumed independently by `run_onchange_after_darwin-38-install-claude-mcp-servers.sh.tmpl`, `-39-install-claude-plugins.sh.tmpl`, `dot_session-index/config.json.tmpl`, and the LaunchAgent, none of which this change touches.
- **Accepted regression**: deleting `home/.chezmoitemplates/claude-environments` removes the only existing validation of `claude_envs`/`claude_default` format anywhere in the repo (the `~/.claude-<name>` shape check and the `claude_default`-must-be-a-member cross-check). This previously incidentally protected the MCP-servers/plugins/session-index scripts above too, not just the removed shell feature — none of which had their own validation. No replacement is added: `for_each_claude_env` (in `scripts/shared-utils.sh`, used by scripts 38/39) already silently skips any declared entry whose directory doesn't exist, which is judged sufficient — a malformed or undeclared entry degrades to a quiet no-op across every consumer (MCP servers, plugins, session-index, and the shell plugin all skip it identically) rather than corrupting anything, and directory *creation* for real entries is unaffected, already handled by the existing, untouched `home/dot_claude-<name>/` chezmoi-managed source directories (see Impact).

## Capabilities

### New Capabilities
*(none — no new chezmoi-owned capability is introduced; the plugin's own behavior is out of this repo's spec scope once extracted, documented instead in the plugin's own README)*

### Modified Capabilities
- `claude-environments`: Most existing requirements are removed (validation, per-env functions, terminal title hooks, the segment definition, the switcher) because the mechanism they describe no longer exists in this repo — it lives in the external plugin, except SpecStory wrapper functions, which move to a small inline block directly in `dot_zshrc.tmpl` (task 5.6) rather than the plugin, since they have no relationship to Claude-environment switching. `Default Environment via Exported Variable` is kept and modified: still exports a default, but from a small inline snippet in both rc templates instead of the old partial, and now reaches every shell (not just terminals inheriting the macOS LaunchAgent's GUI-session variable). `rc File Integration` is rewritten to describe the `.chezmoiexternal.toml.tmpl` entry and the `plugins=()` registration (no more `includeTemplate` calls for the removed partial, no bash *switcher* integration), plus the new inline `claude-spec`/`codex-spec`/`gemini-spec` wrapper-function block (zsh only, task 5.6). `Right-Prompt Registration in p10k Config` is expanded to also cover hosting the plugin's display-preference settings (`CLAUDE_ENV_COLORS`, `CLAUDE_ENV_SHOW_DEFAULT`) as literal `dot_p10k.zsh` values. `GUI Session Inheritance via LaunchAgent`, `Conditional Plist Inclusion`, and `Shared Skills Directory via Symlink` are untouched.
