## Context

See `proposal.md` for motivation. This design emerged from a working session on `clean-claude-orphans` that started as a series of narrow output-format fixes to `list-claude-orphans.sh` and escalated once the question "why does this script depend on `audit-packages` at all?" was asked directly. A first draft of this design was reviewed and revised; see "Review Findings Incorporated" below for what changed and why.

Relevant existing mechanics:

- `home/dot_local/bin/executable_audit-packages.tmpl`'s `main()` (bottom of file) runs unconditionally with no `[[ "${BASH_SOURCE[0]}" == "${0}" ]]` guard — sourcing the file to reuse a function (`declared_for_agent`, `audit_claude_plugins`, ...) would also immediately run the full Homebrew/UV/Bun/Cargo/SDKMAN/Claude audit and print its report. The only interface the script exposes today is its stdout/stderr text.
- `home/.chezmoiignore.tmpl` lists `scripts/` — chezmoi never renders or deploys anything under `home/scripts/`. `home/scripts/shared-utils.sh` is sourced directly from the source tree by every templated script that needs it (`source "{{ .chezmoi.sourceDir }}/scripts/shared-utils.sh"`), and is itself plain bash with no `{{ }}` syntax — it never passes through chezmoi's template engine at all. **Any new file under `home/scripts/` must follow the same rule**: plain bash, no template syntax, because nothing will ever render it.
- `report_orphans` (`audit-packages.tmpl:223`) is the shared diff helper: `comm -23 "$installed_file" "$sorted_declared"`. `comm` pairs lines positionally between two streams — it is not a set-difference over multisets. A duplicate line on the installed side with only one matching line on the declared side leaves exactly one unmatched line behind, reported as an orphan, regardless of whether the underlying item is genuinely declared. `audit_claude_plugins`'s installed-list construction already carries `sort -u` as of this session (fixed directly, ahead of this change); `audit_claude_mcp_servers`'s installed-list construction (`audit-packages.tmpl:673`) already deduped before this session started. Neither the marketplaces nor skills sections build an installed list with a comparable multi-row-per-item source, so they need no equivalent dedup.
- `audit_claude_skills` (via `declared_for_agent "claude_code" "skills"`) and `audit_claude_plugins`'s declared side only ever read `packages.yaml`. Neither has any notion of `home/dot_claude/skills/` (chezmoi-managed skills, deployed by `chezmoi apply`, never through `npx skills add`) or of the chezmoi-personal marketplace (`~/.local/share/claude-plugins/.claude-plugin/marketplace.json`, this repo's own plugin catalog, declared outside `packages.yaml` by design — see `openspec/specs/claude-plugin-marketplace/spec.md`). Both are legitimate "this is accounted for" sources that `audit-packages` simply doesn't know to check. This gap is still open in `audit-packages`; `clean-claude-orphans`' own script already carries a working exclusion for both, added during the same session, using the `@chezmoi-personal` id-suffix rule for plugins (not a marketplace-name cross-reference) — this design reuses that exact rule rather than inventing a second one.
- `clean-claude-orphans/scripts/executable_list-claude-orphans.sh.tmpl` works around the remaining gap itself: it shells out to `audit-packages` (the whole tool) and `LC_ALL=C LANG=C`-forces its output to ASCII so an `awk` state machine can track `=== section ===` boundaries and strip `[INFO]`/`[TIP]`/indented-hint noise, while *separately* re-deriving the marketplace catalog (`jq` against the deployed `marketplace.json`) and the chezmoi-managed skill list (`ls dot_claude/skills/`) to post-filter/tag the scraped orphan lines. This script does not currently check for `yq` or set `PACKAGES_YAML` — it has never needed `declared_for_agent` itself, since it only ever consumed `audit-packages`' *already-diffed* output.
- Precedent for finding and fixing an `audit-packages` bug as a side effect of unrelated work: `openspec/changes/chezmoi-managed-plugin-marketplace/design.md`'s "Implementation Findings" §8 documents `audit_claude_marketplaces`' directory-source `jq` filter bug, discovered and fixed the same way.

## Goals / Non-Goals

**Goals:**
- One function computes "is this Claude Code plugin/skill declared" per category, used by both `audit-packages` and `clean-claude-orphans` — not two independent computations that can (and did) disagree.
- `list-claude-orphans.sh` no longer depends on `audit-packages`' human-readable text format. It calls functions and reads JSON Lines.
- `audit-packages`' own direct-invocation output gets the same correctness fix `clean-claude-orphans` needed, since the underlying bug is in `audit-packages`, not in the skill.
- Keep both scripts as simple as possible: push shared logic into one library file rather than growing either script's own responsibilities.

**Non-Goals:**
- Not changing what a human sees when running `audit-packages` directly — same headers, same stderr hints, same exit codes, same `--strict` behavior.
- Not generalizing this pattern to the non-Claude-Code package managers (Homebrew, UV, Bun, Cargo, SDKMAN) in this change — no evidence surfaced that any of them has a multi-scope-equivalent duplication source, so hardening them is out of scope here.
- Not adding a `--json` output mode to `audit-packages` itself. The shared library is a function-call interface for scripts in this repo, not a new public CLI surface.

## Decisions

**1. New file: `home/scripts/audit-claude-code.sh` — plain bash, not a `.tmpl`.** `home/scripts/` is chezmoiignored (see Context), so a `.tmpl` file placed there would never be rendered; it would be sourced with literal, uninterpreted `{{ }}` text, breaking on the first `source`. The library therefore contains **no chezmoi template syntax at all**. Anything it needs that depends on `.chezmoi.sourceDir` — the `packages.yaml` path, the chezmoi-managed-skills directory path — is supplied by the caller as a plain shell variable, set from the caller's own already-rendered template value, before the `source` line:
  ```bash
  PACKAGES_YAML="{{ $sourceDir }}/.chezmoidata/packages.yaml"
  CHEZMOI_MANAGED_SKILLS_DIR="{{ $sourceDir }}/dot_claude/skills"
  source "{{ $sourceDir }}/scripts/audit-claude-code.sh"
  ```
  The library documents these two required variables in a comment at its own top. (The chezmoi-personal marketplace path needs no such variable — `~/.local/share/claude-plugins/.claude-plugin/marketplace.json` is a fixed deployed path under `$HOME`, independent of where the source checkout lives.) Each caller derives the two variables from its own existing path machinery — `audit-packages.tmpl` already has `$sourceDir := .chezmoi.sourceDir`; `list-claude-orphans.sh.tmpl` uses `.chezmoi.sourceDir` directly today and does not need to introduce a same-named variable to match — the snippet above illustrates the *shape* of what each caller sets, not a literal variable name both files share.
  - Not a dedicated `.chezmoitemplates` partial pulled in via `includeTemplate`: that mechanism exists for content chezmoi's own `includeTemplate` calls expand at *template-render* time, not for a file meant to be `source`d by a running shell script at *execution* time. A plain file sourced directly, like `shared-utils.sh`, is the simpler and already-precedented shape.
  - The library does **not** source `shared-utils.sh` itself and has no `print_message` calls — it is JSONL-only, with no human-facing output whatsoever (see Decision 6). The only shell-availability checks it might need (`claude`, `yq`) are explicitly the caller's job already (Decision 8), so there is nothing in the library that needs `command_exists` either.

**2. New file lives in `home/scripts/`, not a change to `home/scripts/shared-utils.sh`.** `shared-utils.sh` is generic (`print_message`, `command_exists`, `require_tools`) and sourced by every templated script in this repo, including ones with nothing to do with Claude Code. Mixing Claude-Code-specific, `packages.yaml`-reading, `marketplace.json`-reading logic into it would make a general-purpose file single-purpose-coupled. A dedicated file keeps the dependency explicit: only `audit-packages.tmpl` and `list-claude-orphans.sh.tmpl` source it.

**3. The library emits JSON Lines, not the `## section` / TSV shapes `list-claude-orphans.sh` used before this session's earlier fixes.** Matches the JSONL convention already adopted in `clean-claude-orphans` (`{category, item, skill_tag}` for orphans, `skill_tag` always present — `null` when not applicable, never an omitted key) — the library becomes the single place that produces it, rather than `list-claude-orphans.sh` reshaping scraped text into that shape itself.

**4. Declared-set exclusions (chezmoi-personal plugins, chezmoi-managed skills) live inside the library's orphan functions, not as a post-filter the caller applies.** This is the actual point of the refactor: "is this plugin declared" should have one answer, computed once, not filtered after the fact by whichever caller remembered to do it.
  - Plugins: declared = `packages.yaml`'s `plugins` list **union** every installed `.id` ending `@chezmoi-personal`. This is a direct suffix test on the installed id itself — it does **not** go through the marketplace-name catalog, so a plugin installed from the chezmoi-personal marketplace is recognized even if its manifest entry were ever missing or renamed, and there is exactly one rule for "is this chezmoi-personal," reused identically by `claude_orphan_plugins_jsonl` and `claude_installed_plugins_jsonl`.
  - Skills: declared = `packages.yaml`'s deterministic/wildcard matching **union** every name under `dot_claude/skills/` (via the caller-supplied `$CHEZMOI_MANAGED_SKILLS_DIR`).
  - A `bundled-by:<plugin>` skill duplicate is **not** excluded this way — the standalone copy itself genuinely isn't declared by either union member, so it stays an orphan, tagged. The library derives this tag from a single `claude_chezmoi_personal_plugins_jsonl` function (one `{name, skills[]}` object per chezmoi-personal plugin, read from `marketplace.json`) rather than maintaining a second, separately-derived skill→plugin map — `claude_orphan_skills_jsonl` builds the lookup it needs from that same function's output internally. `list-claude-orphans.sh`'s `## chezmoi-personal-plugins` display section calls the identical function for its own output, so the marketplace is read and interpreted in exactly one place.

**5. Dedup the plugins installed list inside the library (`sort -u`), preserving the fix already made.** This fix predates this change (see "Why" in `proposal.md`); the library extraction carries it forward rather than reintroducing the bug. No other category needs the same treatment (see Context).

**6. `audit-packages.tmpl` keeps its own `print_message`/stderr-hint rendering and its own orphan-count bookkeeping; it does not print the library's JSONL directly — and the header/skip-message print order stays the caller's responsibility, not the shared helper's.** The four Claude sections do not all order "header" and "skip" the same way today: `audit_claude_mcp_servers` prints its `skip` message **with no header at all** when no `~/.claude*/settings.json` exists, while `audit_claude_skills` always prints its `=== Claude Code Skills ===` header **first**, then a `skip` message if `~/.claude/skills` is missing. `audit_claude_skills` also prints a wildcard-coverage `print_message "info"` note (when applicable) *between* the header and the orphan list/success message. A single helper that always prints a header and only then decides success-vs-orphans cannot reproduce both orderings, so the new `report_orphan_list_body(items, uninstall_prefix, uninstall_mode)` helper (alongside the existing `report_orphans`) does **only** the part that's identical across all four sections — success-or-echo, `TOTAL_ORPHANS`/`MANAGERS_WITH_ORPHANS` bookkeeping, `print_uninstall_hint` — never the header, never the skip check, never the wildcard note. Each `audit_claude_*` function keeps printing its own header and skip message in today's exact position (see `tasks.md` §2), then calls `claude_skills_wildcard_coverage_note` (skills only) or nothing, then calls the library's orphan function, then calls `report_orphan_list_body`. Two tiny library precondition functions — `claude_mcp_settings_present()` and `claude_skills_dir_present()` — let each caller make the same skip/no-skip decision it makes today without re-deriving the glob/existence check itself; `list-claude-orphans.sh.tmpl` uses the same two functions to skip a category's JSONL output silently (it has no header/skip-message concept to preserve) rather than crashing under `set -e` if a precondition is absent. This is what keeps the output-format requirements in `openspec/specs/package-audit/spec.md` (`Orphan list is plain stdout`, `Uninstall Hint Output`, `Final summary`, `Exit Code Behavior`, and the skills-section-specific scenarios) satisfied without modification — only the *declared-set* requirements change.

**7. `list-claude-orphans.sh.tmpl` prints the library's JSONL directly, with no reformatting.** It has no human-prose contract to preserve (its own `SKILL.md.tmpl` documents the JSONL shape as the interface), so there's no reason to introduce an intermediate representation there.

**8. Library functions fail soft, never hard, under the caller's `set -e`.** Both callers run with `set -euo pipefail`. A library function that lets an external command's non-zero exit propagate would abort the *entire* calling script the first time, e.g., `claude plugins list --json` hiccups — a regression from today, where `audit-packages` catches such failures per-section (via `2>/dev/null`, `|| true`, and the existing text-output fallback parser for `claude plugins list`/`claude plugins marketplace list` when `--json` fails) and continues with the remaining sections. Every library function follows the same defensive style already used throughout `audit-packages` (`cmd 2>/dev/null || true`-type guards) and preserves the existing `--json`-fails-fall-back-to-text-parsing behavior for plugins and marketplaces. Preconditions (`claude` on PATH, the `ai` tag active) remain the caller's responsibility, exactly as today — `audit_claude()`'s existing `command_exists claude` / `has_tag "ai"` checks, and a new equivalent `command -v claude`/`yq` check added to `list-claude-orphans.sh.tmpl` — so library functions can assume those preconditions already hold by the time they're called, and don't duplicate the check.

**9. `declared_for_agent` moves into the library verbatim and is deleted from `audit-packages.tmpl`.** `claude_orphan_plugins_jsonl`, `claude_orphan_marketplaces_jsonl`, and `claude_orphan_skills_jsonl` need it — **`claude_orphan_mcp_servers_jsonl` does not and must not use it.** `audit_claude_mcp_servers` reads its declared set with a *different*, direct query: `yq ".packages.darwin.ai.agents.claude_code.mcp_servers[]?.name" "$PACKAGES_YAML"`. This is a deliberate difference, not an oversight — `mcp_servers` entries in `packages.yaml` are structured maps (`{name, scope, command}`), unlike the plain string arrays `plugins`/`plugin_marketplaces`/`skills` use, so `declared_for_agent`'s generic `.key[]?` query would return whole YAML map objects for `mcp_servers`, which would never string-match an installed server name — every MCP server would be reported as a false orphan. `claude_orphan_mcp_servers_jsonl` therefore ports that direct `.name`-extracting query unchanged, as its own inline `yq` call, not through `declared_for_agent`. `list-claude-orphans.sh.tmpl` has never had access to `declared_for_agent` before (it only ever consumed `audit-packages`' finished output); it depends only on `$PACKAGES_YAML` being set, consistent with Decision 1.

## Review Findings Incorporated

A review pass of an earlier draft of this design (via a separate review agent, not self-reviewed) found one critical and several major issues, all addressed above:

- **Critical**: the original draft proposed `home/scripts/audit-claude-code.sh.tmpl`, sourced directly from the source tree like `shared-utils.sh` — but `home/scripts/` is chezmoiignored, so it would never be rendered, and its `{{ }}` syntax would reach bash as literal text. Fixed by Decision 1 (plain bash, caller-supplied variables).
- The original draft's chezmoi-managed-skills path derivation used an incorrect `../dot_claude/skills` relative path. Fixed: the caller computes the correct absolute path itself (as `list-claude-orphans.sh.tmpl` already does today) and passes it in as `$CHEZMOI_MANAGED_SKILLS_DIR`.
- The original draft had the library call `declared_for_agent` without defining it or its `$PACKAGES_YAML`/`yq` prerequisites anywhere `list-claude-orphans.sh` could reach. Fixed by Decision 9 and the proposal's note that `list-claude-orphans.sh.tmpl` gains a `yq` check.
- The original draft left `list-claude-orphans.sh`'s `## chezmoi-personal-plugins`/`## chezmoi-managed-skills` display sections re-deriving their own data independently of the library, contradicting the stated goal of eliminating duplicate computation. Fixed by Decision 4's last paragraph — those sections now call the same library functions.
- The original draft defined chezmoi-personal membership two different ways in different places (marketplace-manifest lookup vs. id-suffix test). Fixed by standardizing on the id-suffix test everywhere (Decision 4).
- The original draft's Risks section didn't address `set -e` propagation through library functions, or preservation of the existing text-output fallback parsers. Fixed by Decision 8.
- The original draft's tasks list omitted `TOTAL_ORPHANS`/`MANAGERS_WITH_ORPHANS` bookkeeping, which would silently break `--strict`. Fixed by Decision 6 and reflected in `tasks.md`.
- The original draft overclaimed that dedup applies to "every Claude Code comparison." Narrowed in `proposal.md` and the spec delta to plugins specifically, the only category with a demonstrated multi-row-per-item source.
- The original draft's proposal overclaimed that `list-claude-orphans.sh`'s `awk` filter "worked around" the dedup bug. Corrected — that bug was invisible to and unaddressed by the skill's own script; only the declared-set gap was worked around there.

## Risks / Trade-offs

- **[Trade-off] One more file to keep in sync when the Claude Code audit's behavior changes.** Accepted: the alternative (the status quo) is two files silently drifting out of sync, which is the bug this change exists to fix.
- **[Trade-off] `audit-packages`' own declared-set behavior changes for direct users, not just `clean-claude-orphans` users.** This is intentional (see proposal's "Why") — the old behavior was a bug, not a documented feature anyone depended on. Anyone currently reading `code-quality@chezmoi-personal` out of `audit-packages`' plugin section and manually ignoring it will simply stop seeing it.
- **[Resolved, not a risk]** Skills are shared across every `CLAUDE_CONFIG_DIR` persona via a symlink (`~/.claude-<name>/skills -> ~/.claude/skills`, per `claude-tooling.md`), so there is exactly one physical copy of `list-claude-orphans.sh` regardless of how many personas exist on a machine — no multi-copy drift risk from this change. Noted here only because an earlier review pass asked the question directly.
- **[Non-goal, explicitly deferred] `audit_claude_skills`'s installed-side enumeration reads a hardcoded `~/.claude/skills`, not `$CLAUDE_CONFIG_DIR`-relative.** Pre-existing behavior, unrelated to this change; left alone.
- **[Non-goal, explicitly deferred] `audit_claude()`'s `has_tag "ai"` gate doesn't carry over to `list-claude-orphans.sh.tmpl`.** The script has no equivalent check today, and isn't gaining one — it's invoked only through the `clean-claude-orphans` skill, which is itself gated by `{{- if has "ai" .tags -}}` in `SKILL.md.tmpl`, so in practice it never runs on a non-`ai`-tagged machine. Worth stating explicitly rather than assuming, since it's a real (if low-risk) asymmetry with `audit-packages`' own gating.
- **[Behavior to preserve] Missing `marketplace.json` degrades the same way it does today.** `claude_chezmoi_personal_plugins_jsonl` writes an error to stderr and emits nothing when the deployed `marketplace.json` is absent — matching `list-claude-orphans.sh`'s current `else echo "error: marketplace.json not found..." >&2` branch — rather than failing hard. A missing `$CHEZMOI_MANAGED_SKILLS_DIR` degrades the same way (emits no names, not an error exit).
- **[Behavior to preserve] Output ordering stays sorted, matching `sort -u`/glob order, for every category.** This is implicit in "port unchanged" throughout `tasks.md` §1, but worth stating directly: it's part of what "byte-for-byte identical" (the stated non-goal in `proposal.md`) actually requires.
- **[Open question, deferred] Should chezmoi attribute prefixes (`private_`, `executable_`, etc.) be stripped from directory names under `dot_claude/skills/` before comparing against installed skill names?** No skill directory under `dot_claude/skills/` currently uses such a prefix, and today's `list-claude-orphans.sh` doesn't strip them either — so this change introduces no regression either way. Worth a one-line comment in the library if a future skill ever needs a prefix, but not addressed here.

## Second Review Pass Findings Incorporated

A second, independent review of the revised design/tasks found two further MAJOR issues (no criticals), both now fixed above:

- **Major**: `tasks.md` and Decision 9 originally said `claude_orphan_mcp_servers_jsonl` uses `declared_for_agent`, same as the plugin/marketplace/skills functions. It doesn't, and must not — confirmed directly against `audit-packages.tmpl:676`, which runs a different, `.name`-extracting `yq` query because `mcp_servers` entries are structured maps, not plain strings. Implemented as originally written, this would have reported every declared MCP server as a false orphan. Fixed in Decision 9 and `tasks.md` task 1.9.
- **Major**: the original `report_orphan_list` design always printed its own header before deciding success-vs-orphans, which cannot reproduce `audit_claude_mcp_servers`' no-header-on-skip behavior or `audit_claude_skills`' header-then-skip / header-then-wildcard-note-then-list ordering — both confirmed directly against `audit-packages.tmpl` lines 542–550 and 625–650. Fixed by Decision 6: the helper (`report_orphan_list_body`) now only does the success/bookkeeping/hint part, and header/skip/note printing stays in each caller's own function, in today's exact order, backed by two new library precondition functions (`claude_mcp_settings_present`, `claude_skills_dir_present`).
- Minor fixes also applied: task 3.8 (SKILL.md wording) no longer conditioned on "if the shape changed" — `SKILL.md.tmpl`'s own description of running `audit-packages` becomes false regardless of JSONL shape, so it always needs rewording now; Decision 1's code snippet no longer implies both callers share a literal `$sourceDir` variable name; the library no longer sources `shared-utils.sh` (it has no use for `print_message`, and precondition checks were already the caller's job).

## Post-Approval Revision: Relocated to `dot_local/lib/` as a Real Template

After architect approval and the mandatory deslop pass, the library was relocated from `home/scripts/audit-claude-code.sh` (plain bash, Decision 1 above) to `home/dot_local/lib/audit-claude-code.sh.tmpl`, deployed by `chezmoi apply` to `~/.local/lib/audit-claude-code.sh`.

**Why this works**: `home/dot_local/lib/` is not listed in `home/.chezmoiignore.tmpl` (confirmed directly — grep returns nothing), so chezmoi renders and deploys it normally, unlike `home/scripts/`. The library can therefore contain real `{{ .chezmoi.sourceDir }}` template syntax and compute its own `PACKAGES_YAML`/`CHEZMOI_MANAGED_SKILLS_DIR` at render time, rather than requiring each caller to set them as plain shell variables beforehand (Decision 1's original constraint). Both callers simplify to a single line — `source "$HOME/.local/lib/audit-claude-code.sh"` — with no preceding setup.

**What this costs**: editing the library now requires `chezmoi apply` before either caller sees the change, same as every other `dot_local/` deployment in this repo (`audit-packages.tmpl` itself already has this property). The previous design's one advantage — editing `home/scripts/audit-claude-code.sh` took effect immediately, matching `shared-utils.sh`'s zero-apply-step convenience — is traded away. Accepted: this repo's universal rhythm is "edit + `chezmoi apply`" for everything under `home/` except the handful of files `scripts/` deliberately exempts, and a sourced-but-unrendered library was the unusual case, not the deployed-and-rendered one.

**Verification redone end-to-end**: `home/scripts/audit-claude-code.sh` was removed (`git rm`); `home/dot_local/lib/audit-claude-code.sh.tmpl` renders cleanly (`tests/run-template` + `bash -n`); both callers were updated to drop their `PACKAGES_YAML`/`CHEZMOI_MANAGED_SKILLS_DIR` setup and the old sourcing line, and re-rendered/re-syntax-checked. Since sourcing now uses a fixed `$HOME`-relative absolute path (no longer PATH-shadowable the way an executable is), the new deployed file was manually placed at `~/.local/lib/audit-claude-code.sh` (previously nothing existed there) to verify the full flow live, rather than running a full `chezmoi apply`. Re-ran every previously-fixed regression case — the exit-code-on-missing-skills-dir fix and the `set -e` resilience-under-failing-`claude` fix — both still hold with the new sourcing path; output otherwise byte-identical to every prior verified run.
