## Context

See `proposal.md` for motivation. This design emerged from an `/opsx:explore` session on 2026-08-20 that started from a different premise ("move `chezmoi-personal` to its own GitHub repo, rename it, declare it in `plugin_marketplaces`") and pivoted once the actual underlying concerns were named directly. Relevant existing mechanics:

- `packages.darwin.ai.agents.claude_code.{mcp_servers,skills,plugin_marketplaces,plugins}` in `home/.chezmoidata/packages.yaml` are installed user-scope by `run_onchange_after_darwin-37/38/39` — governed by the `package-management` spec. `run_onchange_after_darwin-39-install-claude-plugins.sh.tmpl` already loops over `plugin_marketplaces` and calls `claude plugins marketplace add "$source" --scope user --scope user` for each, per persona via `for_each_claude_env`. Entries are inserted into a bash array as `MARKETPLACES+=('{{ . }}')` — single-quoted, so no shell expansion happens on the templated value.
- `chezmoi-personal` (`.claude-plugin/marketplace.json` + `plugins/`, both at the repo root, outside `home/`) is registered separately by `run_onchange_after_darwin-44-register-claude-plugin-marketplace.sh.tmpl`, which computes its source as `dirname {{ .chezmoi.sourceDir }}` (this repo's own root) and calls the same `claude plugins marketplace add ... --scope user` per persona. It currently holds 10 marketplace.json entries: 5 locally-authored (`aws-local-dev`, `browser-tools`, `openspec-dashboard`, `serena`, `fast-filesystem` — physically under `plugins/`) and 5 pure re-pointers with no local content (`code-quality`, `systems-design`, `atlassian`, `aws-core`, `cloudflare` — `source` is entirely a third-party git/URL object).
- `audit-packages`'s `audit_claude_marketplaces` / `report_orphans` only ever computes `installed ∖ declared` (`comm -23`) — a one-directional check for extras. It has no mechanism, and this change adds none, for detecting "declared but not currently installed" drift (e.g. a manually-removed marketplace). That gap is pre-existing, applies to every package manager this repo audits, and is explicitly out of scope here.
- `clean-claude-orphans/SKILL.md.tmpl` currently hardcodes: *"Name is `chezmoi-personal`, or its `source` is a local directory (no `repo`/`url`) resolving to this repo's root → NEVER an orphan."* This exists only because `chezmoi-personal` is genuinely undeclared in `plugin_marketplaces` today.
- The current `claude-plugin-marketplace` spec requires (a) the marketplace's own registration is a local path into the chezmoi *source* tree, and (b) marketplace/plugin content is explicitly **not** chezmoi-templated or deployed — both requirements this change reverses.
- `openspec/changes/archive/2026-08-12-move-project-plugins-to-marketplace/` is the precedent for this marketplace's `.mcp.json`-bundling and `source`+`skills`-array plugin shapes; those requirements are unaffected by this change.
- The basic-memory note [[Auditing and Removing the basic-memory-workflow Plugin]] (`chezmoi/reference/auditing-and-removing-the-basic-memory-workflow-plugin`) is the precedent for propagating a `chezmoi-personal` marketplace change to every machine, not just the one it was implemented on — its two lessons (enumerate personas per-machine rather than assuming a fixed list; cross-check raw `settings.json` in addition to the CLI) shaped tasks.md's per-machine section 3 structure.

## Goals / Non-Goals

**Goals:**
- Eliminate the darwin-44 dedicated-script special case; registration flows through the same generic mechanism every other marketplace uses.
- Eliminate the `clean-claude-orphans` hardcoded exception — `chezmoi-personal` becomes genuinely declared, not specially recognized.
- Make plugin/marketplace content chezmoi-templatable (available, not necessarily used immediately).
- Preserve as much of today's fast edit loop as reasonably possible: accept "edit + `chezmoi apply`" (already this repo's universal rhythm) rather than a push/pull/marketplace-update cycle.
- Get personally-identifying `name`/`email` out of committed plain JSON in `marketplace.json`'s `owner` and each `plugin.json`'s `author`, now that templating is available to do it (see Decision 7) — this is the one specific templating use this change makes, not just enables.

**Non-Goals:**
- Not moving to a separate GitHub repository (see Alternatives Considered).
- Not renaming the marketplace or any plugin.
- Not adding new automation for per-project plugin enablement.
- Beyond the `owner`/`author` `name`/`email` fields (Decision 7), not templating any other plugin file content yet — this change otherwise only makes templating possible for future use.

## Decisions

**1. Target path: `home/dot_local/share/claude-plugins/` → deployed to `~/.local/share/claude-plugins`.** Fixed and portable, independent of where the chezmoi source tree happens to be checked out — unlike today's `dirname .chezmoi.sourceDir`, which breaks if the repo is cloned to a different path. This portability is exactly what makes a plain string entry in `plugin_marketplaces` possible at all; a literal path into the source checkout would still be machine-specific and couldn't live in static `packages.yaml`.
   - Alternative considered: nest under `~/.claude/plugins-local/` or similar, or as a new `~/.claude-plugins` sibling of the persona dirs — both rejected. Nesting inside `~/.claude/` risks confusion with Claude Code's own `~/.claude/plugins/` cache directory (where installed plugin *content* actually materializes per persona) and is conceptually wrong besides: this marketplace is registered identically across *every* persona, so it doesn't belong inside any single persona's config tree. A `~/.claude-plugins` sibling was also rejected — every existing `~/.claude-<name>` in this repo denotes a `CLAUDE_CONFIG_DIR` persona (`.claude-personal`, `.claude-work`, `.claude-bedrock`); a non-persona directory matching that shape would be actively misleading, not just superficially similar. `~/.local/share/` sidesteps both problems and matches existing precedent in this repo: `home/dot_local/bin/` already deploys to `~/.local/bin`, and `.chezmoiexternal.toml.tmpl` already deploys third-party tool content (`zsh-llm-suggestions`, `freshbooks-mcp-server`, `zsh-functions`) into `~/.local/share/*`.

**2. Registration via the generic `plugin_marketplaces` list, not a dedicated script.** Removes darwin-44 entirely. Requires a small fix to darwin-39: today's `MARKETPLACES+=('{{ . }}')` is single-quoted, so a `$HOME`-relative literal wouldn't expand under bash. At implementation time, either (a) declare the entry as `$HOME/.local/share/claude-plugins` and switch that one array insertion to allow expansion, or (b) write the `packages.yaml` entry as an already-resolved-at-render-time value using `{{ .chezmoi.homeDir }}` (or equivalent), since the *script* is templated even though `packages.yaml`'s data is not — the expansion can happen in the Go-template layer instead of the shell layer. Prefer (b) if available: it avoids introducing a second quoting convention into the same array for different entry types.

**3. One persona-independent path, not one per persona.** `~/.local/share/claude-plugins` is shared across all personas (default, personal, work, bedrock), matching today's behavior — one repo-rooted `plugins/` tree, registered identically for every persona via `for_each_claude_env`. This change relocates the existing shared tree; it doesn't introduce per-persona plugin content. Worth being explicit about since every other recent `dot_claude-*` addition in this repo *is* persona-specific (`dot_claude-personal`, `dot_claude-work`) — placing this content under `dot_local/share/` instead of `dot_claude-*` keeps it out of that family entirely, rather than relying on a reader to notice one `dot_claude-*` entry among several means something different.

**4. Attribute-encode the moved tree for chezmoi.** 11 files today. Every leading-dot path component gets the `dot_` prefix, not just the top-level `.claude-plugin/`: each of the 5 local plugins (`aws-local-dev`, `browser-tools`, `fast-filesystem`, `openspec-dashboard`, `serena`) has its own `.claude-plugin/plugin.json` → `dot_claude-plugin/plugin.json` and `.mcp.json` → `dot_mcp.json`. Plugin *directory* names (`aws-local-dev/`, etc.) stay plain, no `dot_` prefix — only actual dot-prefixed files/dirs need it. No `private_`/`executable_` needed since nothing here is secret or a script. Two categories of file additionally need `.tmpl` — see Decision 7.

**5. Delete the orphaned `plugins/basic-memory-workflow/` leftover as part of this move**, not a separate change — it's dead weight in the exact tree being relocated.

**6. Spec delta reverses two requirements, revises one in place.** "Marketplace and plugin content are not chezmoi-templated" is removed outright and replaced with its opposite (title changes, so modeled as REMOVED + ADDED rather than MODIFIED). "Marketplace source is a plain local path" and "Marketplace registration is chezmoi-bootstrapped and idempotent" keep their titles and behavioral intent (still local, still idempotent) but their mechanism descriptions change substantially, so both are MODIFIED in place.

**7. Template `owner`/`author` `name` and `email` using `.fullname` and `.gh_commit_email` — reject `.reverse_dns`.** `marketplace.json`'s `owner` and each local `plugin.json`'s `author` currently hardcode `"name": "Craig Earley"` and `"email": "craig@craigearley.software"`. `.reverse_dns` was the originally-proposed source for email; checking `.chezmoi.toml.tmpl` showed this is wrong — `.reverse_dns` computes `io.github.cearley`, a reverse-DNS bundle identifier used only for macOS LaunchAgent labels (`private_Library/LaunchAgents/{{ .reverse_dns }}.claude-config-dir.plist.tmpl`), not an email address. The two real options were `.gh_commit_email` (existing field, already used by `dot_gitconfig.tmpl` for the same purpose) or a new dedicated `personal_email` field defaulting to the current hardcoded address; the user chose the former. `.fullname` was correct as originally proposed and needed no change.
   - **Known consequence, not a bug**: `.gh_commit_email` currently renders to `cearley@users.noreply.github.com` (confirmed via `chezmoi execute-template`), not `craig@craigearley.software`. The deployed `marketplace.json`/`plugin.json` email value changes as a result of this decision — a GitHub noreply address instead of a personal one, which is a further step in the same direction as the motivating request, but a real rendered-output change worth being explicit about rather than assuming it's cosmetic.
   - `owner.url` (`https://github.com/cearley/dotfiles`) is left hardcoded — a public repo URL carries no comparable exposure, and templating it wasn't asked for.

## Alternatives Considered

**Move to a separate GitHub repository**, declared as a remote marketplace source, with a rename away from `chezmoi-personal` — the originally-explored direction. Rejected:
- It trades today's zero-step "edit `plugins/X`, it's immediately live" loop for a commit-push-then-`marketplace update` cycle. Real cost: the last 5 commits touching this marketplace span 2026-08-06 through 2026-08-17 — active, roughly-every-few-days iteration.
- It doesn't resolve either concern that motivated this change. The orphan-detection fragility is a `packages.yaml`-declaration problem, not a which-repo-hosts-the-content problem, and a local declared path fixes it just as well. The "two parallel config-management systems" discomfort was about chezmoi never managing this content at all (no apply, no templating) — a different repo doesn't fix that, it relocates the same disconnection into a second repo.
- A repo-identity/scope framing ("does a plugin marketplace belong in a dotfiles repo's brand") was considered and, once named directly, wasn't actually the concern.

**Leave darwin-44 as-is; just add a documentation-only entry to `plugin_marketplaces`** (no relocation). Rejected: `plugin_marketplaces` entries are actively *installed* by darwin-39 (`claude plugins marketplace add`), not passively documented — declaring the same marketplace at a different path than where darwin-44 actually registers it would double-register it or conflict, unless the two paths are made identical, which reduces to this proposal's approach minus the templating benefit.

**Inline `aws-local-dev/.mcp.json`'s `LOCALSTACK_AUTH_TOKEN` directly via `keepassxcAttribute`, dropping `mcp-env-wrapper`** — raised once this change made plugin files templatable in principle (Decision 7 already templates `plugin.json`'s `author` fields, so why not `.mcp.json`'s secret too?). Rejected, out of scope for this change, based on direct inspection of `~/.claude-personal/plugins/cache/chezmoi-personal/aws-local-dev/<hash>/.mcp.json`:
- Enabling any plugin — at **any** scope (`user`, `project`, or `local` — confirmed via this repo's own archived task notes, which show `user`-scope enablement triggering the same behavior) — makes Claude Code copy the plugin's full file content into a per-persona, commit-hash-versioned cache under `~/.claude-<persona>/plugins/cache/<marketplace>/<plugin>/<hash>/`. This is outside chezmoi's management entirely: chezmoi cannot set permissions on it, clean it up, or even know it exists.
- The cached `.mcp.json` copy is `-rw-r--r--` (0644, world-readable), confirmed by direct inspection — not the `0600` chezmoi applies to `private_`-prefixed files.
- If the real token were embedded in `.mcp.json.tmpl`, it would be duplicated into that 0644 cache the moment the plugin is installed anywhere, again for every persona that installs it, and again for every historical version as the plugin updates (stale hash-directories persist rather than being deleted — one `basic-memory-workflow` cache entry has a `.orphaned_at` marker instead of removal).
- The current `mcp-env-wrapper` approach avoids all of this by design: the cached `.mcp.json` copy contains only the wrapper invocation (`"command": "mcp-env-wrapper", "args": [...]`), never a secret. The real value lives in exactly one place, `home/private_dot_config/mcp-env/private_localstack-mcp-server.env.tmpl` → `~/.config/mcp-env/localstack-mcp-server.env` (0600, chezmoi-managed), read fresh at process-launch time. No amount of plugin caching duplicates it.
- Conclusion: `mcp-env-wrapper` stays for any plugin-bundled MCP server needing a secret. This reinforces (doesn't just coexist with) the existing non-goal that this change touches only `owner`/`author` identity fields, not other plugin file content — that boundary turns out to be load-bearing, not just conservative scoping.

## Implementation Findings

**8. `audit-packages`'s directory-source bug was the real cause of the "null" line, not undeclared status.** Discovered during implementation (task 4.3): declaring `chezmoi-personal` in `plugin_marketplaces` alone did *not* make it disappear from `audit-packages`'s orphan output — `audit_claude_marketplaces`'s installed-side `jq` filter only handles `.source == "github"` (→ `.repo`) and falls through to `.url` for everything else; a directory-sourced marketplace has neither, only `.path`, so it always produced the literal string `"null"`. This is exactly the artifact the old `clean-claude-orphans` "null"-skip line (removed in this change, Decision/task 4.1) was silently working around — but the bug is in `audit-packages` itself, independent of declaration status, and would misreport *any* directory-sourced marketplace, declared or not. Fixed the `jq` filter to read `.path` for `.source == "directory"`, and added a real shell `$HOME` expansion on the declared side (`packages.yaml`'s `$HOME/.local/share/claude-plugins` is a literal, non-templated string — chezmoi can't expand it at render time, so the fix expands it via `sed` at script-invocation time instead) so both sides compare as equal absolute paths. Confirmed via `audit-packages` re-run: the Plugin Marketplaces section now reports "No orphans".

## Risks / Trade-offs

- **[Risk] Migration on already-provisioned machines.** Existing machines have `chezmoi-personal` registered at the old source-tree path. Left alone, the new `plugin_marketplaces` entry would try to add a *second* registration under the same name at a different path — likely erroring or conflicting. → Mitigation: a task to `claude plugins marketplace remove chezmoi-personal` (old registration, per persona) before/during the transition, not left implicit.
- **[Risk] Existing `enabledPlugins` entries reference the marketplace by name** (`<plugin>@chezmoi-personal`). Since the name is unchanged, these should keep resolving once re-registered at the new path — but this should be a verification task, not an assumption.
- **[Trade-off] Loses the literal zero-step edit loop** (source tree == served content) in favor of "edit + `chezmoi apply`". Accepted as consistent with this repo's universal rhythm for everything else under `home/`.
- **[Trade-off] Deployed email value changes** from `craig@craigearley.software` to `cearley@users.noreply.github.com` (Decision 7). Confirmed as an accepted, understood consequence of choosing `.gh_commit_email`, not an oversight.
