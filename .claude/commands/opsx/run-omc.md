Run one OpenSpec change end to end without a human in the loop after kickoff: preflight, delegate implementation to OMC `executor` agents one phase at a time, mark tasks from evidence, run verification, and loop on findings until clean or out of iterations.

This command orchestrates directly. It does not use `opsx-omc-bridge`, `autopilot`, `ralph`, or `team` — each of those is a second orchestrator with its own task truth (PRD stories, autopilot plan, team task list) competing with `tasks.md`. `tasks.md`, read and written only by this session, is the single source of progress.

**Input**: a change slug, e.g. `/opsx:run-omc replace-opsx-omc-bridge-with-run-omc`. Optional: `--max-iterations N` (default 3). If the slug is omitted, run `openspec list --json`, show active changes with remaining-task counts, and ask the user to pick. Never guess.

**Steps**

1. **Preflight** (read-only)

   ```bash
   bash .claude/scripts/opsx-preflight.sh "<slug>"
   ```

   - `validation: FAIL` → stop. Show the errors; point to `/opsx:update <slug>` or `/opsx:continue <slug>`.
   - `tasks: total=N complete=N remaining=0` (no remaining tasks) → stop. Suggest `/opsx:verify <slug>` then `/opsx:archive <slug>`.
   - `stale_prd:` present → tell the user; it is irrelevant to this command (ralph is not used) but will confuse any later ralph run.
   - `dirty_tree_files` > 0 → tell the user the count and confirm they want to proceed on a dirty tree. This is the only question asked before the run.

2. **Load the handoff**

   ```bash
   openspec instructions apply --change "<slug>" --json
   ```

   Keep: `contextFiles` (read every file listed: proposal, design, delta specs, tasks), the pending task list, and `context`. `context` comes from `openspec/config.yaml`'s chezmoi-specific `context` block, reused as-is. (This installed OpenSpec CLI version does not surface `config.yaml`'s `rules:` block — proposal/spec/tasks authoring guidance — through `openspec instructions apply --json`; that block is consumed by the authoring skills, not apply. Don't reference an `operationGuidance` field — it doesn't exist in this CLI's output.)

   Group pending tasks by the `## N.` phase headers in `tasks.md`. If there are no headers, treat all pending tasks as one phase.

3. **Implement, one phase at a time**

   For each phase with pending tasks, spawn one subagent with the Agent tool: `subagent_type: "oh-my-claudecode:executor"` (no model override — always the executor's pinned default), `isolation: "worktree"` only for parallel phases. Subagents run in the background; wait for the completion notification before step 4 and never infer a result before it arrives. Prompt shape:

   ```
   Implement one phase of OpenSpec change <slug> in this repo.

   ## Project context
   <context from step 2>

   ## Rules (binding)
   - Do NOT edit openspec/changes/<slug>/tasks.md. Report completed tasks; the orchestrator marks them.
   - Work alone. Do not spawn team workers, autopilot, ralph, or opsx-omc-bridge; read-only explore agents are fine.
   - On ambiguity or scope beyond the spec: stop and return BLOCKED with the exact question. Do not guess.
   - Never commit, push, or archive this OpenSpec change under any circumstance — those remain explicit, separate user decisions after the final report.

   ## Artifacts
   proposal.md: <full text>
   design.md: <full text>   (architectural decisions are binding)
   delta specs: <full text> (GIVEN/WHEN/THEN are the acceptance criteria)

   ## Your tasks (this phase only)
   <pending tasks of this phase, verbatim, with their original numbering>

   ## Already complete (do not redo)
   <tasks already [x], one line each>

   ## Return format
   Use your normal `## Changes Made / ## Verification / ## Summary` layout. Inside `## Summary`, list one line per assigned task:
   `DONE <task text> — evidence: <files changed, commands run and their output>` or `NOT DONE <task text> — reason`.
   ```

   If the agent returns BLOCKED, stop the whole run and surface the question to the user.

   Phases run sequentially by default. Run two phases in parallel only when `tasks.md` names disjoint files for each and the design has no ordering between them; in that case give each agent `isolation: "worktree"` and merge the worktree branches yourself before step 4. When in doubt, sequential.

4. **Mark tasks** (this session is the single writer)

   For every `DONE` line with evidence that checks out (the named files were actually changed, the named commands actually ran and produced the claimed output), flip that task's `- [ ]` to `- [x]` in the tasks file. Leave `NOT DONE` and unevidenced tasks unchecked. Re-run `openspec instructions apply --change "<slug>" --json` and record `progress`.

5. **Verify**

   Build the changed-file list once:
   ```bash
   { git diff --name-only main...HEAD; git status --porcelain | cut -c4-; } | sort -u
   ```
   Make new files visible to diff-based review without staging or committing them. `code-review` reads the git diff, which excludes untracked files, so new files an executor creates go unreviewed unless intent-added first:
   ```bash
   git ls-files --others --exclude-standard | sort | comm -13 .claude/.cache/untracked-baseline.txt - | tee .claude/.cache/untracked-new.txt | xargs -r git add -N
   ```
   Only files that were not untracked at preflight are marked (the baseline is written by `opsx-preflight.sh`), so pre-existing scratch files stay out of the review. After this step completes, `xargs -r git reset -q -- < .claude/.cache/untracked-new.txt` so the tree is left exactly as the executors wrote it. Intent-to-add is index-only; nothing is committed.

   Then run these in parallel (all read-only). Spawn every agent/skill below in one message so they run concurrently:
   - Invoke the `code-review` skill with effort `medium`. Never `--fix` (fixes go through the executor with evidence) and never `max`/`ultra`. It reviews the base branch to the working tree, so run `run-omc` on a fresh branch per change or earlier commits will be reviewed too. CONFIRMED findings are blockers; PLAUSIBLE findings are advisory. This is the only pass that checks whether the logic is correct; `opsx:verify` checks artifact conformance and `template-reviewer` checks template conventions.
   - Invoke the `opsx:verify` skill with `<slug>`. Collect CRITICAL / WARNING / SUGGESTION.
   - If any `.tmpl` file was added or modified during the run: Agent `subagent_type: "template-reviewer"` with the changed-file list. Its findings are blockers. If no `.tmpl` file changed, skip this pass and note it was skipped in the report.

6. **Fix loop**

   If `code-review` has CONFIRMED findings, `opsx:verify` has CRITICAL findings, or `template-reviewer` (when run) reports a blocker, and iterations remain:
   - Dispatch one fresh `oh-my-claudecode:executor` with the same Rules and Artifacts blocks plus a `## Findings to resolve` block containing every blocker verbatim (source pass named) and the tasks still unchecked.
   - Then repeat steps 4 and 5.
   Stop when every pass is clean, when the executor returns BLOCKED, or when `--max-iterations` is reached.

7. **Report**

   ```
   ## OpenSpec Run: <slug>

   READY TO MERGE / BLOCKED

   ### Implementation
   - Phases: N (sequential | parallel via worktrees)
   - Iterations used: n / max
   - Tasks: N/M complete; still unchecked: [list or none]

   ### code-review (medium)
   - CONFIRMED: file:line — ... / none   <- blockers
   - PLAUSIBLE: ...                       <- advisory

   ### /opsx:verify
   - CRITICAL: ... / none
   - WARNING: ...

   ### template-reviewer
   - run (findings) | skipped (no .tmpl changes)

   ### Next
   - BLOCKED: what remains, then re-run `/opsx:run-omc <slug>`
   - READY: review the diff; ask the user whether to commit (then, separately, whether to push); then `/opsx:archive <slug>`
   ```

**Hard rules**
- Never commit, push, or archive the OpenSpec change from this command, under any circumstance. Those actions remain explicit, separate user decisions after the final report.
- Never edit `tasks.md` except in step 4, and only with evidence.
- Never report READY TO MERGE while any verification pass has an unresolved blocker.
- Never answer an agent's question on the user's behalf. Surface it and stop.
- Never invoke `opsx-omc-bridge`, `autopilot`, `ralph`, or `team` from this command, and tell every executor it spawns the same. This command is the only orchestrator and `tasks.md` the only truth.
